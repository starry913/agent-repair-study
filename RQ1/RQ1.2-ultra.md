# RQ1.2：不同任务中的 subtask pathway 是否存在共同规律？

`Distinct` 表示一条轨迹中出现的 subtask 类型数。为避免总体结果掩盖任务差异，我们依据 reference patch 将任务分为单文件单点、单文件多点、模块内多文件和跨模块多文件。任务分类仅用于分层比较，分析目标是寻找跨任务共享的 pathway 规律。

## 1. 是否存在跨任务共享的核心 pathway？


| 任务类型     | `D=4` | `D=5` | `D=6` | 重复 `FR -> FL` | 重复 `PV -> PR` |
| -------- | ----- | ----- | ----- | ------------- | ------------- |
| 单文件单点修复  | 24.9% | 55.0% | 19.9% | 79.3%         | 16.1%         |
| 单文件多点修复  | 19.0% | 57.1% | 23.7% | 81.3%         | 25.5%         |
| 模块内多文件修复 | 19.2% | 46.2% | 33.3% | 87.2%         | 23.1%         |
| 跨模块多文件修复 | 11.5% | 53.8% | 33.8% | 88.5%         | 29.2%         |


`D=6` 表示轨迹在五类基本 subtask 之外包含 `PR`；重复 `FR -> FL` 和重复 `PV -> PR` 分别表示对应转换至少出现两次。

**Finding 1：APR agent 在不同任务上共享“问题理解、失败复现、故障定位、补丁生成、补丁验证”的基本修复流程。随着任务范围扩大，agent 更频繁地在基本流程后增加补丁优化，并重复执行复现-定位；但进一步跨越模块后，流程组成和复现-定位循环趋于稳定，新增工作集中到重复验证-优化。** 因为包含五类 subtask 的轨迹在四类任务中始终占比最高。从单文件单点、单文件多点到模块内多文件，包含 `PR` 的六类路径依次由 19.9% 升至 23.7% 和 33.3%，重复 `FR -> FL` 也依次由 79.3% 升至 81.3% 和 87.2%。进一步跨越模块后，六类路径仅增至 33.8%，重复 `FR -> FL` 仅增至 88.5%，但重复 `PV -> PR` 由 23.1% 增至 29.2%。

## 2. `FR -> FL` 循环中的哪些因素产生收益，哪些因素造成消耗？

首先复用总体循环统计。零轮到一轮的 RR 仅由 0.776 升至 0.800，差异不显著（双侧比例检验，`p=0.673`）；一轮以后 RR 开始下降。

| `FR -> FL` 循环次数 | n | RR |
| --- | ---: | ---: |
| 0 | 67 | 0.776 |
| 1 | 215 | 0.800 |
| 2 | 334 | 0.719 |
| 3-4 | 351 | 0.661 |
| 5+ | 524 | 0.731 |

为解释这一变化，我们依据 reference patch 判断轨迹第几轮首次到达 fault-relevant 源码目标。单元为 `n / 组内占比 / RR`。

| 总循环数 | 第一轮首次到达 | 第二轮首次到达 | 第三轮及以后首次到达 | 始终未到达 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 195 / 90.7% / 0.810 | - | - | 20 / 9.3% / 0.700 |
| 2 | 149 / 44.6% / 0.671 | 173 / 51.8% / 0.780 | - | 12 / 3.6% / 0.417 |
| 3-4 | 65 / 18.5% / 0.677 | 231 / 65.8% / 0.688 | 32 / 9.1% / 0.562 | 23 / 6.6% / 0.478 |
| 5+ | 448 / 85.5% / 0.763 | 37 / 7.1% / 0.676 | 24 / 4.6% / 0.542 | 15 / 2.9% / 0.200 |

下表进一步计算每个循环位置的边际定位产出。“新增有效目标”表示该轮首次到达或补充了 reference source file；“确认已有有效目标”表示继续检查此前已经到达的 reference source file。

| 循环位置 | n | 扩展任意新候选 | 新增有效目标 | 确认已有有效目标 | 无有效定位增量 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 第 1 轮 | 1424 | 91.2% | 60.2% | 0.0% | 39.8% |
| 第 2 轮 | 1209 | 70.4% | 37.9% | 40.6% | 21.5% |
| 第 3 轮 | 875 | 38.1% | 6.1% | 65.3% | 28.7% |
| 第 4-5 轮 | 1161 | 25.3% | 1.8% | 72.7% | 25.5% |
| 第 6 轮及以后 | 1573 | 8.3% | 0.4% | 64.0% | 35.6% |

**Finding 2：失败复现与故障定位的有效窗口集中在前两轮：第一轮用于直接定位，第二轮用于补救延迟定位；第三轮以后，循环由发现新故障位置转为确认已有目标或无效定位，新增定位收益基本耗尽。** 一轮轨迹中，90.7% 在第一轮到达有效目标；两轮轨迹中，51.8% 依靠第二轮完成首次有效定位，RR 仍为 0.780。到第三轮，新增有效目标的概率由前两轮的 60.2% 和 37.9% 降至 6.1%，第三轮以后才首次到达目标的 RR 也降至 0.562。与此同时，第三轮确认已有有效目标和无有效定位增量的比例分别升至 65.3% 和 28.7%；第四轮以后，两者合计始终超过 95%。5+ 轮轨迹的 RR 回升并不表示长循环有益：其中 85.5% 早在第一轮就已到达有效目标，后续循环主要是在确认已有位置；第六轮以后新增有效目标的概率仅为 0.4%。因此，积极因素是前两轮完成首次有效定位，消极因素是定位仍未收敛却继续循环；循环是否应停止，应由边际定位产出而不是累计轮数决定。

## 3. `PV -> PR` 循环由哪些机制主导？

后循环根据 `PR` 与当前 patch 的结构关系编码。判定只比较连续 edit 的文件、旧文本和新文本，不使用修改是否与 reference patch 一致。

| 机制 | 可复现判定 |
| --- | --- |
| 重改同一代码位置 | 当前 edit 继续修改上一轮刚改过的代码片段 |
| 在原文件补充修改 | 在已经修改的文件中编辑新的代码位置 |
| 转向新文件修改 | 开始修改当前 patch 尚未涉及的文件 |
| 撤销或替换已有修改 | 当前 edit 恢复或整体替换此前修改的核心内容 |

单元为 `n / 事件占比 / 所在轨迹 RR`。小于 10 个事件的单元仅为完整呈现，不用于形成 finding。

| 首次 `PC` | 循环次数 | 重改同一代码位置 | 在原文件补充修改 | 转向新文件修改 | 撤销或替换已有修改 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `PC+` | 1 | 93 / 44.7% / 0.720 | 66 / 31.7% / 0.727 | 31 / 14.9% / 0.677 | 18 / 8.7% / 0.722 |
| `PC+` | 2 | 99 / 59.6% / 0.646 | 22 / 13.3% / 0.682 | 8 / 4.8% / 0.625 | 37 / 22.3% / 0.811 |
| `PC+` | 3-4 | 144 / 51.4% / 0.556 | 67 / 23.9% / 0.642 | 10 / 3.6% / 0.600 | 59 / 21.1% / 0.644 |
| `PC+` | 5+ | 432 / 54.1% / 0.486 | 156 / 19.5% / 0.615 | 36 / 4.5% / 0.417 | 174 / 21.8% / 0.557 |
| `PC-` | 1 | 14 / 46.7% / 0.500 | 5 / 16.7% / 0.200 | 10 / 33.3% / 0.800 | 1 / 3.3% / 0.000 |
| `PC-` | 2 | 14 / 41.2% / 0.429 | 4 / 11.8% / 0.750 | 8 / 23.5% / 0.625 | 8 / 23.5% / 0.500 |
| `PC-` | 3-4 | 25 / 55.6% / 0.200 | 6 / 13.3% / 0.333 | 6 / 13.3% / 0.333 | 8 / 17.8% / 0.625 |
| `PC-` | 5+ | 82 / 67.2% / 0.366 | 18 / 14.8% / 0.278 | 6 / 4.9% / 0.667 | 16 / 13.1% / 0.375 |

**Finding 3：后循环的有效机制取决于首次 patch 是否已经建立正确方向：错误首补丁需要转向新文件或撤销原方案，正确首补丁则更适合在原文件补充遗漏修改；重改同一代码位置对两者都有害。** 当 `PC-` 时，第一轮转向新文件修改的 RR 为 0.800，高于重改同一代码位置的 0.500；到 3-4 轮，撤销或替换已有修改仍有 0.625，而重改同一代码位置降至 0.200。对 `PC+`，五轮以上在原文件补充修改达到 0.615，重改同一代码位置和转向新文件修改分别只有 0.486 和 0.417。原始 diff 表明，成功的 `PC-` 往往把修改从错误的抽象层移到调用者、编译器、字段处理或并列后端；失败的深循环则反复改写上一版代码而没有改变根因假设。因此，积极补救的本质是反馈改变了 patch 的结构或修改位置，消极循环的本质是新反馈只产生局部措辞和条件微调。

## 小结

循环次数只描述表面长度。前循环的价值取决于能否在前两轮形成新的有效定位；后循环则取决于反馈能否改变 patch 的结构或修改位置，而非持续改写同一位置。
